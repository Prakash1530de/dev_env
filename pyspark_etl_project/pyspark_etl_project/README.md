# PySpark ETL Project — Retail Sales Pipeline

A small, runnable ETL project using **Python, PySpark, SQL, and YAML configuration**. It reads sample CSV files, cleans and validates records, enriches sales with product data, and writes curated outputs.

## Requirements

- Python 3.10 or 3.11 recommended
- Java compatible with your installed PySpark version (Java 11 or 17 is commonly used with current Spark distributions)
- PySpark

## Setup

Create and activate a virtual environment, then install dependencies:

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

## Run

From the project root:

```bash
python -m src.main
```

The pipeline:
1. Reads `data/input/sales.csv` and `data/input/products.csv`.
2. Casts fields and removes invalid records (missing IDs, invalid dates, non-positive quantities, or negative prices).
3. Joins sales with products and calculates `line_total`.
4. Writes curated sales as Parquet and rejected rows as CSV under `data/output/`.

Output paths are configured in `config/config.yaml`. The first Spark run may take a little time to start.

## SQL files

- `sql/create_tables.sql` contains example DDL for a relational warehouse target.
- `sql/data_quality_checks.sql` contains example SQL checks for a loaded `fact_sales` table.

The included pipeline writes Parquet files; it does not automatically connect to a database. Adapt `src/load.py` and the SQL DDL for your chosen warehouse (PostgreSQL, SQL Server, Snowflake, etc.).

## Configuration

Edit `config/config.yaml` to change input/output paths, Spark settings, and quality rules. Paths are resolved relative to the project root.

## Notes

This is a learning/demo project, not production-hardened. For production, add secrets management, structured logging, orchestration (Airflow/Databricks), schema evolution, retries, monitoring, and integration tests.
